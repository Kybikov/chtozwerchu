# Реліз 1.34 — керування автосном сцени

Музична сцена, окремі локальний і мережевий TV-екрани та сцена конкурсів
тепер запитують утримання екрана через Screen Wake Lock API. На підтримуваних
пристроях кнопка «Без автосну» показує, що браузер надав запит. Натиск
дозволяє звичайне згасання, повторний натиск знову запитує утримання.
Активний стан позначений лаймовим кольором і aria-pressed.

При згортанні сцена звільняє запит. Після повернення видимої сторінки
запит повторюється, якщо ведучий не вимкнув цю можливість. Вихід зі сцени
звільняє утримання, зокрема якщо браузер відповів на запит із затримкою.
Системне скасування або відмова не запускають нескінченних повторів.
Кнопка дозволяє спробувати ще раз; на браузерах без API вона не показується.
Особисті пульти не отримують цієї функції. Успішне утримання не запускає
музику й не знімає ігрову паузу.

Кнопка використовує наявний React Bits SpecularButton. Нових залежностей,
таймерів опитування, налаштувань ОС чи дозволів для сторонніх сервісів немає.

## Перевірка й межі

107 фронтенд-тестів, typecheck, production build, Go tests і vet пройшли.
Сім тестів перевіряють відкладений результат після виходу, приховану сторінку,
повернення, відмову, системне звільнення та відсутність паралельних запитів.
У справжньому браузері API надав запит локальному TV, сцені конкурсів і
музичній сцені; перевірено ручне вимкнення й повторне ввімкнення. В особистому
пульті кнопки немає. Панель не має горизонтального переповнення на 320,
1280 і 3840 px.

Автоматичний таймер фізичного телевізора та реальне згортання встановленого
PWA на Android/iOS у цій перевірці не тестувались. Підтримка залежить від
браузера: енергозбереження або низький заряд можуть скасувати утримання.
Джерела: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API),
[специфікація W3C](https://www.w3.org/TR/screen-wake-lock/).

Повне аудіо Deezer залишається [незавершеним](music-playback.md).
