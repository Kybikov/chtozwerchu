# Реліз 1.28 — відновлення вікна після невдалого оновлення

Після помилки встановлення PWA або відсутньої відповіді інших вікон
діалог пропонує «Відновити це вікно». Дія завантажує поточну оболонку
з сервера, зберігаючи екран, параметри кімнати та фрагмент URL.
Вона доступна тільки між активними діями в цьому вікні; перевірка
зайнятості повторюється безпосередньо перед переходом.

Рахунок, програма, власне аудіо й мітки залишаються у сховищах цього
походження. Інші вікна не перезавантажуються. Дія не активує очікуючий
worker і не очищує кеші чи сховища. Для відновлення потрібен інтернет.
Звичайне встановлення PWA продовжує вимагати готовності всіх вікон.

`GET /api/app-shell` повертає index.html поточної збірки без редиректу,
з `no-store` та забороною індексації. Цей шлях виключений з навігаційного
кешу вже опублікованих worker. Після завантаження main.tsx повертає
канонічний кореневий URL без нової навігації, тому вікно знову бере
участь у чинному протоколі перевірки активності PWA. HEAD не повертає
тіло; методи зміни даних відхиляються.

В ізольованому браузері початковий протокол успішно активував як
мінімальний worker із чинним захистом, так і production Workbox.
Це не підтверджує причину тайм-ауту старої публічної вкладки: її
недоступність для браузерного керування не є доказом дефекту гри.

## Перевірка

92 фронтенд-тести, production build, повний набір Go-тестів і vet пройшли.
Два нові серверні тести перевіряють отримання поточного HTML після зміни
файлу, відсутність редиректу, no-store, HEAD та відхилення методів зміни.

В ізольованому браузерному профілі з production Workbox навмисно створено
очікуючий worker без обробника встановлення. Після тайм-ауту справжній
діалог показав резервну дію; її натискання виконало новий мережевий запит
`/api/app-shell?screen=studio`. Свіжа збірка відновила 3:0, програму з
чотирьох власних пісень, 30-секундне аудіо на паузі та мітки слів.
URL повернувся до кореня без втрати screen. Несправний worker залишився
очікувати, інше контрольне вікно не перезавантажилося. Вхід із роллю
remote зберіг code і фрагмент URL; відсутня контрольна кімната показала
штатне повідомлення пульта.

На 320 × 800 діалог прокручується всередині без горизонтального
переповнення. На 1920 × 1080 нова дія видима без прокручування;
діалог має ширину 640 px. Власне аудіо після відновлення відтворюється,
а під час відтворення встановлення оновлення знову недоступне.

Повні треки Deezer залишаються [незавершеними](music-playback.md).
