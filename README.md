# Хто зверху? — онлайн

## Домашнє шоу — версія 1.37

Головна пропонує два формати: музичну студію `/?screen=studio` та вечір
п’яти конкурсів `/?screen=party`. Реєстрація необов’язкова. Акаунти мають
приватну історію завершених партій, cookie-сесії та вихід із відкликанням
сеансу. [послівні мітки Deezer 1.13](docs/release-1.13.md), [деплой](DEPLOY.md).

Новий фронтенд: React 19 + TypeScript + React Bits. Реалізований локальний
конкурс «Продовж пісню»: дві команди, пошук Deezer, прихована відповідь,
прив’язка рядка до аудіо, автоматична зупинка перед ним, оцінка ведучого,
рахунок, історія, фінал і окреме вікно сцени для телевізора.
Типографіка Oswald + Onest та власна музична графіка.
У вечорі конкурсів ведучий обирає звук на своєму пристрої або на TV,
керує гучністю з пульта. «Правда чи брехня» підтримує спільну відповідь
та індивідуальні голоси активної команди з телефонів. Мелодії можна
вгадувати наввипередки: перший сигнал зупиняє звук і дає 10 секунд на відповідь.
Режим «Пульт на телефоні» використовує серверні кімнати: окремий приватний
пульт, екран зі звуком та глядацькі екрани. Сервер керує фазами, оцінкою й
таймером. Кімнати з Redis працюють через кілька серверів і відновлюються
на паузі після втрати власника. Пульт, гравці й TV можуть підключатися
до різних вузлів за балансувальником.

### Запуск нової версії

Потрібні Node.js 22.12+ та Go 1.24+.

```powershell
npm ci
npm run build
npm start
```

Відкрити `http://127.0.0.1:5599`. Для розробки окремо запустити
`npm run dev`: Vite на `http://127.0.0.1:5173` проксує API на порт 5599.
Порт API можна змінити через `MUSIC_API_URL` у середовищі Vite.

Deezer надає публічний пошук та 30-секундні прев’ю. Для синхронізованого
тексту додати **на бекенді**, у проігнорований `.env.local`, `DEEZER_ARL`
або `DEEZER_ACCESS_TOKEN`. ARL поновлює JWT; один JWT працює лише до спливу
його терміну. Секрети не мають префікса `VITE_` і не потрапляють у фронтенд.
Прототип не під’єднується до бази WTAdmin самостійно.

### Реальна синхронізація

- Позиція: `audio.currentTime * 1000 + offsetMs`. Окремого таймера тексту немає.
- Прев’ю не містить позиції у повному записі. Ведучий прив’язує початок
  почутого рядка до поточної позиції плеєра й перевіряє збіг.
- Власний повний файл можна відкрити локально, скоригувати прив’язку або
  підтвердити часову шкалу повного запису. Потрібна відповідна версія треку.
- Імпорт `.lrc` зберігає часові мітки; Enhanced LRC підтримує точні мітки
  окремих слів. Редактор біля кожного рядка записує мітки слів під аудіо,
  дає поправити їх і експортувати назад у LRC. Джерела без міток слів
  залишаються на рівні рядків. Текст, останній аудіофайл і метадані
  зберігаються в IndexedDB; рахунок і налаштування — в localStorage.
- Вікно прив’язки має власне перемотування та прослуховування окремого рядка.
  Воно зупиняється в кінці рядка й не починає раунд. Рядки поза аудіо недоступні.
- «Загадати» обирає прихований рядок. «Почати раунд» відтворює обрані 5, 7, 10 або 15 секунд
  перед ним і зупиняє музику. Ведучий нараховує 3 бали одній команді або
  завершує раунд без балів. Повторне натискання не подвоює оцінку.
- Перемикання вкладки ставить музику на паузу. Перезавантаження відновлює
  налаштування та файли, але не запускає аудіо самостійно.

### Мережевий пульт

1. Підготуй трек і текст на пристрої, що відтворюватиме звук.
2. Натисни «Пульт на телефоні» → «Підключити телефон».
3. Дозволь звук на сцені та відкрий приватне посилання на телефоні ведучого.
4. Пульт запускає фрагмент, ставить музику й таймер на паузу, зараховує бали,
   виправляє поточну оцінку, змінює пісню та прив’язку рядків.

Публічний екран отримує тільки сцену без прихованих рядків. Ключ пульта
передається у фрагменті посилання, зникає з адресного рядка після відкриття
і не потрапляє до HTTP-логів. Повторне відкриття приватного пульта передає
керування новому вікну. Перезапуск сервера не відновлює музику автоматично.

З REDIS_URL основний стан і координація кімнат зберігаються в Redis.
STUDIO_STATE_DIR задає приватні резервні файли; npm start використовує
output/studio-state, Docker Compose — том studio_state. Без Redis прямий
запуск Go використовує пам’ять і ці файли. Для Vite можна задати STUDIO_API_URL,
а MUSIC_API_URL визначає джерело музичного API.

### Межі прототипу

Партія має 4, 8, 12 або 16 ходів, час на відповідь, історію та фінал.
Ведучий може виправити поточну оцінку. Завершений раунд і фінал переживають
перезавантаження. «Окреме вікно для TV» синхронізує сцену в цьому ж браузері
через BroadcastChannel; передай її на другий екран. Звук іде з пристрою ведучого.

Музична студія підтримує локальну гру та мережевий пульт. Для фізичного
телефону адреса сайту має бути доступна з його мережі: localhost у телефоні
не відкриє сервер ноутбука. Поточний приватний перегляд через SSH лишається
локальним. Публічний сайт у Coolify доступний через HTTPS, у тому числі
з телефона. Акаунти та п’ять конкурсів інтегровані в новий React-інтерфейс;
повне захищене відтворення Deezer ще не інтегроване.
Deezer надає таймінги рядків та послівні мітки для частини каталогу.
Доступний тип підсвічування явно показаний у студії й пульті. Для інших
записів є ручна розмітка та Enhanced LRC. Таймінги слів не вигадуються.
Класичний інтерфейс залишений у `web/` і доступний через
`/classic/` при налаштованому `LEGACY_WEB_DIR`.

PWA кешує оболонку та локальні шрифти. Без мережі працює підготовлена локальна
гра зі збереженим аудіофайлом і текстом; API й зовнішні прев’ю не кешуються.
Встановлення потребує HTTPS або localhost. Оновлення застосовується вручну
та недоступне під час відтворення ігрового фрагмента.

Перевірки: `npm test`, `npm run build`, у `server/` — `go test ./...` і
`go vet ./...`. Дизайн та походження компонентів: `docs/music-studio.md`.

## Стек

- **Бекенд:** Go 1.24, `net/http` + `gorilla/websocket` (realtime-хаб).
- **Стан кімнат:** Redis, один власник з lease/fencing, pub/sub між вузлами;
  без Redis — локальний сервер із приватними файловими знімками.
- **Дані:** PostgreSQL (`pgx/v5`) — каталог пісень/питань, юзери, історія матчів.
- **Фронт:** статичний SPA (`web/`) на WebSocket, дизайн під «Хто зверху».
- **Деплой:** docker-compose (postgres + redis + app).

## Запуск через Docker Compose

Повна інструкція деплою (Coolify + SSH) — [`DEPLOY.md`](DEPLOY.md).

```bash
docker compose up --build
```

Відкрий: `http://127.0.0.1:3000`

Сервіси: `postgres`, `redis`, `app` (порт 3000). При першому старті БД
автоматично мігрує й засівається каталогом (пісні з `custom-songs.json`,
питання/слова/загадки з `server/internal/store/seed/`).

## Локальна розробка без Docker

Каталог можна вантажити напряму з ембед-сідів (без Postgres/Redis):

```bash
cd server
DATABASE_URL="" REDIS_URL="" PORT=5599 WEB_DIR=../web go run ./cmd/server
```

Відкрий: `http://127.0.0.1:5599`

> `DATABASE_URL=""` / `REDIS_URL=""` (порожні, але **задані**) вимикають
> персистенцію. Якщо змінні не задані взагалі — використовуються дефолти
> для docker-compose (`postgres://khz:khz@localhost:5432/...`).

## Змінні середовища

| Змінна | Призначення | Дефолт |
|---|---|---|
| `PORT` | HTTP-порт | `3000` |
| `DATABASE_URL` | Postgres DSN (порожній → embedded) | локальний postgres |
| `REDIS_URL` | Redis URL (порожній → без Redis) | локальний redis |
| `WEB_DIR` | тека зі статикою | `./web` |
| `PUBLIC_URL` | базовий URL для інвайт-лінків | авто з браузера |

## Акаунти (гість + реєстрація)

Грати можна гостем (лише імʼя). Реєстрація зберігає історію матчів і статистику.
Працює лише коли підключено Postgres (у embedded-режимі повертає 503).

| Метод | Ендпоінт | Призначення |
|---|---|---|
| POST | `/api/auth/register` | `{email, password, displayName}` → `{token, user}` |
| POST | `/api/auth/login` | `{email, password}` → `{token, user}` |
| GET | `/api/me` | (Bearer) профіль + статистика |
| GET | `/api/me/history` | (Bearer) останні матчі |

Токен (`Authorization: Bearer …`) можна передавати у WS-повідомленнях
`create_room`/`join` полем `authToken` — тоді матч зараховується акаунту.
